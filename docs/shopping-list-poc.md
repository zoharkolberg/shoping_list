# ניסוי היתכנות — תוכנית ביצוע ובדיקות
גרסה 0.2 | 27.11.2026 | סטטוס לפי מטריצת הבדיקות ותיעוד Task 003

## מטרה
אימות ההנחות הקריטיות של מסמך התכנון 0.10, לפני פיתוח האפליקציה המלאה. להשתמש בנתוני דמה בלבד. אין להרחיב OAuth scopes או להפעיל שירות בתשלום ללא אישור. שני חשבונות Google נפרדים A (בעלים) ו-B (משתתף), macOS עם שני פרופילי דפדפן ו-iPhone אמיתי. בדיקת Android נדחית עד לפני שחרור רשמי של תמיכה ב-Android. אין צורך למסור סיסמאות או אסימונים למפתח או לצ'אט.

## 1. סביבת עבודה ותצורה

1. לפתוח את `zoharkolberg/shoping_list` ב-Codex Web עם סביבת הענן. לרענן מול `origin/main`, לקרוא את AGENTS.md ולפתוח ענף משימה לשלב המאושר. להכין PR לסקירה. מיזוג, שינוי הגדרות GitHub או פרסום דורשים אישור מפורש. ב-Mac אפשר לעיין ב-PR דרך הדפדפן, ללא התקנת Git או עורך מקומי.
2. בעל הפרויקט אימת את טעינת דף האבחון בכתובת `https://zoharkolberg.github.io/shoping_list/poc/`. אחרי אישור פרסום, לבדוק את כתובת Pages בפועל, HTTPS, נתיבים יחסיים מתחת לנתיב המאגר ופעולת OAuth ו-Picker. להשתמש בתצוגה מקדימה של Codex לניסויים אם היא זמינה. לבדיקת OAuth בתצוגה המקדימה דרוש Origin שאפשר לאשר במפורש. הצלחה בתצוגה המקדימה אינה משלימה את H01.
3. אחרי אישור שינויי Google Cloud, בעל הפרויקט יוצר פרויקט POC נפרד מייצור, בודק מכסות ומצב חיוב ומפעיל Google Drive API, Google Sheets API ו-Google Picker API. שירות בתשלום דורש אישור. ב-Google Auth Platform מגדירים Branding, ובחשבונות Gmail אישיים בוחרים External ו-Testing ומוסיפים את A ו-B כ-Test users. לבדוק בנפרד פקיעת אסימון והצורך בחידוש הסכמה ב-Testing.
4. יוצרים OAuth Client מסוג Web application, עם Authorized JavaScript origins לפי הטבלה. Origin כולל scheme, host ו-port אם נדרש, ללא נתיב המאגר. מודל GIS Token אינו דורש שרת redirect. מגבילים את מפתח Picker ל-Google Picker API ול-Website referrers המאושרים, כולל `https://docs.google.com/*` לפי תיעוד Google. REST משתמש ב-OAuth token. בודקים את מגבלות המפתח בפועל.

| הגדרה | מציין מקום | שימוש |
|---|---|---|
| Google Cloud project ID | `<GOOGLE_CLOUD_POC_PROJECT_ID>` | זיהוי פרויקט הניסוי במסוף |
| Google Cloud project number | `<GOOGLE_PROJECT_NUMBER>` | Picker App ID |
| Web OAuth Client ID | `<GOOGLE_CLIENT_ID>` | GIS Token Client |
| Restricted Picker API key | `<GOOGLE_API_KEY>` | Picker בלבד |
| Authorized JavaScript origins | `<POC_ORIGIN>`, `<APPROVED_PREVIEW_ORIGIN>` אם נדרש | Pages ותצוגה מקדימה שאושרה |
| Website referrers | `<POC_REFERRER_PATTERN>`, `<GOOGLE_PICKER_REFERRER_PATTERN>`, `<APPROVED_PREVIEW_REFERRER_PATTERN>` אם נדרש | הגבלות למפתח Picker |
| Branding ו-Test users | `<APP_DISPLAY_NAME>`, `<SUPPORT_EMAIL>`, `<DEVELOPER_CONTACT_EMAIL>`, `<TEST_ACCOUNT_A>`, `<TEST_ACCOUNT_B>` | הזנה ישירה במסוף בידי הבעלים בלבד |

ערכי המדיניות הקבועים הם ה-scopes `drive.file`, `openid`, `email`. בשלד משתמשים במצייני מקום עד שבעל הפרויקט יאשר את ערכי התצורה הציבוריים. אין להוסיף client secret, refresh token או כתובות חשבונות בדיקה לקוד או ללוג.

## 2. תוכנית מימוש לשלב הראשון

מסך בדיקה סטטי קטן ב-HTML, CSS ו-Vanilla JavaScript, עם כפתורי פעולה נפרדים ותוצאות מסוננות. GIS ו-Picker נטענים כשנדרשים. קריאות Google עוברות דרך שכבת REST משותפת. משתמשים בקובצי דמה בלבד. IndexedDB ותור מלא, ממשק מוצר, קטלוג מלא ו-Service Worker שייכים לשלבים הבאים.

1. **GIS וזהות (A01–A04).** לבקש אסימון בעקבות לחיצה. לאמת שה-scopes הדרושים הוענקו, לקרוא UserInfo ולקשור את האסימון ל-`sub` שנבדק לפני קריאות לקבצים. לשמור אסימון בזיכרון בלבד. לדמות פעולה ממתינה השייכת ל-A ולנסות להפעיל אותה אחרי חיבור B. בדיקת הרשת צריכה להראות אפס כתיבות עם חשבון שגוי. לבדוק ביטול או פקיעה, עצירת כתיבה, חידוש יזום וחסימת קובץ דמה שהאפליקציה לא פתחה. את בדיקת התור המתמשך משלימים בשלב 2.
2. **יצירה ואימות (D01–D03, S01).** לייצר `list_id` יציב לפני Drive `files.create`. ליצור קובץ Google Sheets בבעלות A עם MIME מתאים ו-`appProperties` במצב `initializing`. לשמור את `spreadsheet_id` שהתקבל בהקשר הניסוי, לאתחל `Items`, `Categories` ו-`Metadata` באמצעות Sheets, ולקרוא חזרה את הסכמה והזהות לפני סימון `ready`. לבדוק append ועדכון נקודתי ב-`RAW`, וקריאה ב-`UNFORMATTED_VALUE`. לא לבצע retry עיוור של יצירה אם התגובה אבדה. ניסוי התאוששות מלא שייך ל-S09. לשנות שם ולהעביר תיקייה לקובץ הדמה ולבדוק שהמזהים נשארים קבועים.
3. **שיתוף ו-Picker (D04, D06).** בפרופיל A לבדוק בעלות ו-`canShare`, ולשתף במפורש עם B בלבד דרך Drive Permissions. בפרופיל B לבדוק `files.list/get` לפני בחירה ולתעד את התוצאה. לפתוח Picker עם אסימון B, App ID, מפתח מוגבל, Origin ומסנן Sheets. אחרי בחירה, לבדוק את אותו מזהה דרך Drive ו-Sheets, כולל MIME, `Metadata`, סכמה, התאמה ל-`appProperties` כשזמינים ו-`capabilities`. אין ליצור עותק. לבדוק שצופה אינו כותב, שעורך משנה פריט דמה, ושניהול שיתוף מתאים לתפקיד.
4. **גילוי חוזר (D03, D05).** להריץ `files.list` עם MIME, `trashed=false`, סינון לפי `appProperties` או תחילית שם קובץ הדמה ודפדוף עד הסוף. אם המאפיינים הפרטיים חסרים בקובץ משותף, מאמתים את זהותו באמצעות Metadata ואתחול באמצעות מבנה הלשוניות והנתונים. לסגור את הדפדפן של B ולפתוח מחדש, לקבל אסימון חדש לפעולת הבדיקה ולאמת את `sub`. לחפש את הרשימה ולפתוח את אותו `spreadsheet_id` ללא Picker נוסף בתרחיש רגיל. אם התוצאה שונה, לתעד בנפרד אילו תוצאות התקבלו ב-`files.list`, ב-`files.get` וב-Sheets, בלי להרחיב הרשאות. אם מזוהים קבצים שונים עם אותו `list_id`, לעצור כתיבה לשניהם ולדווח על ההתנגשות.
5. **הרצה וקבלה (H01).** ב-macOS לבצע את תרחישי A ו-B בשני פרופילי דפדפן נפרדים. ב-iPhone אמיתי לפתוח את כתובת Pages המאושרת ב-Safari ולבדוק חיבור, פתיחת Picker וגישה לקובץ הדמה לאחר בחירה. בדיקת התקנת PWA ומצב טיסה שייכת ל-O06. לתעד גרסאות, מזהי מבחן, קודי תוצאה וראיה מסוננת. שער 1 דורש את כל הבדיקות המסומנות בו לפני פיתוח ענן מלא.

## 4. סדר ביצוע ושערי מעבר (Go/No-Go)

1. לממש את שלב ההרשאות והקובץ המשותף בסעיף 2 ולעבור את שער 1.
2. לבנות מעטפת מקומית, IndexedDB ותור אטומי. לבדוק עבודה ללא רשת, כשל עסקה, פתיחה מחדש, פעולות שנוספו תוך כדי סנכרון ושני טאבים (O01–O05, S15–S16).
3. להשלים את שער 2 עם סנכרון, פתרון התנגשויות, כתיבות לא ודאיות ובדיקת זהות קובץ. לתעד גם S02–S03 ו-S11–S14.
4. לבצע את ניסויי המרוצים בנפרד ולעבור את שער 3 בהחלטת בעל הפרויקט.
5. להשלים בדיקות מכשירים, הרשאות, עומס ומוכנות לפרסום לפי שער 4. לתעד ניסיון iPhone כחלק מה-POC. לבצע בדיקת Android לפני שחרור התמיכה בו.

- שער 1: A01–A04, D01–D06, S01, H01 עוברים. אחרת אין להתחיל פיתוח ענן מלא.
- שער 2: O01–O05, S04–S06, S08–S10, S15–S16 ו-D10 עוברים או שקיימת מגבלה מתועדת שאושרה במפורש. אובדן תור או ערבוב חשבונות הם חסמים.
