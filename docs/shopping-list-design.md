# אפליקציית רשימות קניות משותפות — מסמך אפיון ותכנון

גרסה 0.10 | 27.11.2026 | בסיס מאושר לניסוי היתכנות; אישור סופי לאחר POC

## 1. מטרות וגבולות
אפליקציית Web/PWA בעברית ו-RTL, למחשב, טלפון וטאבלט, לניהול רשימות קניות ומשימות אישיות ומשותפות. בעל הרשימה מחזיק את הקובץ ב-Google Drive שלו. אין Backend, מסד נתונים מרכזי, Framework, מערכת Build או איסוף שימוש. יעד עלות אפס, בכפוף למכסות ותנאי השירות. עבודה מקומית מלאה לאחר הכנה ראשונית מקוונת; גם יצירה ושכפול רשימות בבעלות המשתמש ללא אינטרנט. שיתוף וניהול הרשאות דורשים חיבור. אין סנכרון כשהאפליקציה סגורה.

## 3. אפיון פונקציונלי ומסכים
- כניסה ראשונית: Google, זיהוי חשבון, איתור רשימות שלהן האפליקציה מורשית והורדת עותקים מקומיים. עבור קובץ משותף אפשר לאשר גישה באמצעות Picker. בפתיחה הבאה הצגה מקומית מיידית; חידוש חיבור בענן לפי צורך.
- מסך ראשי: רשימות בבעלותי ומשותפות איתי, שם, סוג, מונה פתוחים/הושלמו, חיווי הרשאות וסנכרון. יצירה, פתיחה, שינוי שם לבעלים, שכפול, שיתוף, העברה לאשפה, הסתרה ושחזור מהסתרה. סדר שימוש אחרון מוצע.
- יצירה: שם וסוג shopping/general; אישית כברירת מחדל. אפשרות עבודה מיידית גם לפני יצירת הקובץ בענן.
- רשימת קניות: שדה הוספה קבוע, השלמה בעברית, כמות ברירת מחדל 1, יחידה ומחלקה מהקטלוג. הוספה חופשית. חלון עריכה כולל הערות. סימון בלחיצה אחת, ביטול סימון, מחיקה עם Undo ל-5 שניות. מחלקות ריקות מוסתרות; מיון אישי לפי מחלקות ואלפביתי בתוכן. אזור נרכשו סגור; מונה התקדמות; איפוס באישור, ללא מחיקה.
- כפילויות: נרמול שם וכינויים, התאמת יחידה, הצעת הגדלת כמות או שורה נפרדת. אין המרה אוטומטית בין יחידות; הערות שונות עשויות להצדיק שורות נפרדות. לפריט שנרכש מוצעת החזרה או הוספה נפרדת.
- רשימה כללית: שם, הערות, סטטוס, קטגוריות אופציונליות; כמות ויחידה אופציונליות. ללא קטלוג סופרמרקט.
- שיתוף: בעלים, עורך וצופה; לפי מייל. בחירה באמצעות Picker, ללא העתקת הקובץ. ניהול הרשאות בידי בעלים; עורכים מנהלים פריטים ומחלקות; צופים משנים העדפות תצוגה בלבד. שכפול כפוף להרשאות העתקה ולכלל החיבור בהחלטה 42.
- הגדרות: סדר מחלקות, קטלוג אישי (עריכה/מחיקה), רשימות מוסתרות, מצב מקומי, סנכרון עכשיו, שינויים ממתינים, חשבון, התקנה, פרטיות, גרסה. ערכת תצוגה בהירה/כהה/מערכת מוצעת.
- התנגשויות: חיווי לא חוסם; מקור/מקומי/ענן; בחירה או ערך מותאם. בדיקה מחדש לפני אישור.
- נגישות: RTL, תוויות, מקלדת, יעדי מגע גדולים, חיווי טקסט בנוסף לצבע, תמיכה במסכים קטנים.

## 4. ארכיטקטורה
UI → services → IndexedDB (נתונים ותור באותה עסקה) → sync → REST Google APIs. Service Worker שומר מעטפת וקובצי JSON בלבד. GIS ו-Picker נטענים לפי צורך מקוון; כשל בטעינתם לא חוסם את הממשק המקומי. Google Sheets הוא מקור משותף בענן; התצוגה מבוססת על מצב מקומי עם פעולות ממתינות. GitHub Pages מספק קוד סטטי בלבד.

## 5. מודל ענן
קובץ Sheets אחד לכל רשימה; מזהה פנימי list_id (UUID) נוצר מקומית; spreadsheet_id מתקבל מ-Google. אין מספר שורה כמזהה. תיקיית Shopping Lists אופציונלית לארגון בלבד. שם הקובץ ב-Drive הוא שם הרשימה. אם לאחר גילוי, Picker או התאוששות נמצאים שני spreadsheet_id שונים לאותו list_id, מסמנים התנגשות זהות לפני כתיבה או שיוך מחדש של רשומה מקומית. חוסמים כתיבה לשני הקבצים עד להכרעה מפורשת.

### Items (שורת כותרות 1)
| עמודה | שדה | סוג / כלל |
|---|---|---|
| A | item_id | UUID קבוע |
| B | name | טקסט לא ריק |
| C | quantity | מספר חיובי; אופציונלי בכללית |
| D | unit_id | מזהה יחידה מוכרת; אופציונלי בכללית |
| E | category_id | מזהה מחלקה; אופציונלי בכללית |
| F | completed | Boolean |
| G | notes | טקסט אופציונלי |
| H | created_at | ISO 8601 UTC |
| I | updated_at | ISO 8601 UTC; לא להכרעת התנגשויות |
| J | deleted | Boolean; מחיקה לוגית |

### Categories
A category_id (קבוע, מובנה או UUID), B name, C is_builtin (Boolean), D active (Boolean). כל המחלקות ברשימה נשמרות בגיליון. other תמיד פעילה. שינוי שם אינו משנה מזהה. הסרה: מעבר למחלקת יעד והשבתה באותה בקשת Batch ככל שניתן. פריט עם שיוך לא פעיל יוצג תחת אחר ויקבל חיווי לתיקון.

### Metadata
A key, B value: app_type=shopping_list, schema_version=1, list_id, list_type=shopping/general, created_at. Drive appProperties: app_type, list_id, schema_version, initialization_status=initializing/ready. מאפיינים פרטיים לאפליקציה; בעת מעבר פרויקט Cloud אין להניח שהם נגישים לפרויקט החדש. אימות Metadata גם לאחר Picker. אין לשמור הרשאות בגיליון.

### כללי תקינות
כותרות ומבנה נבדקים לפני כתיבה; UUID כפול או מבנה לא מוכר חוסמים כתיבה לאזור הבעייתי. RAW לכתיבה, UNFORMATTED_VALUE לקריאה. מיון רק בתצוגה; אין מחיקה פיזית, מיון פיזי או שינוי עמודות ב-Sheets כחלק משימוש נתמך. תאריכים אינם שעון סמכותי. שינוי ידני בגיליון נתמך רק בערכים תקינים; שינוי מבני עלול לגרום לעדכון שורה שגויה. לבדוק Developer Metadata ב-POC; אין הבטחה שהוא פותר כל מרוץ.

## 6. אחסון מקומי
IndexedDB בשם shopping_lists_db; גרסה נפרדת מגרסת הקוד ומגרסת Sheets. מפתחות מורכבים לפי account_id (Google sub) ו-list_id. שמונה מאגרים:
| מאגר | מפתח | נתונים |
|---|---|---|
| accounts | account_id | email, last_login_at; ללא token |
| lists | account_id,list_id | spreadsheet_id, name, list_type, owned_by_me, can_edit/share/copy, hidden, cache_ready, sync_status, last_synced_at, last_opened_at, remote_snapshot |
| items | account_id,list_id,item_id | כל שדות Items ומצב אחרון בענן |
| categories | account_id,list_id,category_id | שדות Categories ומצב אחרון בענן |
| personal_catalog | account_id,product_id | name, normalized_name, aliases, preferred_category_id/name, preferred_unit_id, usage_count, last_used_at, updated_at |
| preferences | account_id,setting_key | סדר אישי, סדר מותאם לרשימה, תצוגה |
| operations | operation_id | חשבון, רשימה, סוג, יעד, base_values, changes, sequence, created_at, status, retry_count, last_error, depends_on |
| conflicts | conflict_id | חשבון, רשימה, יעד, operation_id, field/group, base/local/remote, detected_at, status |

אינדקסים לפי חשבון/רשימה/מצב. מטא-דאטה של הרשאות הוא צילום מצב בלבד. עדכון נתון ותור באותה עסקת IndexedDB, אישור למשתמש רק לאחר commit. אין למחוק שינויים ממתינים אוטומטית. cache_ready רק לאחר הורדה מלאה. בקשת navigator.storage.persist() אינה הבטחה למניעת מחיקה. עותקים מקומיים אינם מוצפנים באופן עצמאי. הפרדה לפי חשבון אינה בידוד קריפטוגרפי.

## 7. קטלוג וסדר תצוגה
products.json: product_id, name, aliases[], default_category_id, default_unit_id. יעד מוצע 200–300 מוצרי יסוד ישראליים, ללא מותגים. categories.json: category_id, name, default_order, icon אופציונלי. units.json: unit_id, name, short_name.
מחלקות מוצעות: ירקות ופירות; לחמים ומאפים; חלב ותחליפים; ביצים; בשר ועוף; דגים; קפואים; שימורים; אורז/פסטה/קטניות; תבלינים ואפייה; שמנים ורטבים; חטיפים וממתקים; משקאות; ניקיון ומשק בית; טיפוח והיגיינה; תינוקות; חיות מחמד; אחר. יחידות: יחידות, ק״ג, גרם, ליטר, מ״ל, חבילה, בקבוק, קופסה, שקית, מארז, צרור.
נרמול רווחים ופיסוק וכינויים; התאמה מדויקת, תחילית, כינוי, חלקי; דירוג שימוש אישי. העדפה אישית גוברת על מובנית; אם מחלקה מותאמת אינה קיימת, חיפוש שם מקביל או ברירת מחדל/אחר. למידה אינה משנה רשומות קיימות. סדר אישי נשמר במכשיר, מחלקה חדשה לפני אחר, מיון עברי באמצעות Intl.Collator. אין סנכרון קטלוג אישי בין מכשירים.

## 8. סנכרון ו-Offline
כל שינוי נשמר מקומית תחילה. מנוע אחד לחשבון בכל מתחם אחסון; לבדוק Web Locks ו-BroadcastChannel ותוכנית חלופה. אין נעילה בין מכשירים. מחזור: אימות חשבון והרשאה → קריאת ענן → קריאת תור וגרסאות בסיס → מיזוג → כתיבה נקודתית → אימות לפי הצורך → עדכון snapshot ותור בעסקה → רענון תצוגה. פעולות חדשות שנוצרו בזמן המחזור אינן נדרסות ואינן מסומנות כאילו נשלחו. Pull משמר overlay של פעולות מקומיות.

סוגי פעולה: CREATE_LIST, RENAME_LIST, DELETE_LIST (אשפה), ADD_ITEM, UPDATE_ITEM, DELETE_ITEM, RESTORE_ITEM (או UPDATE_ITEM), RESET_COMPLETED, ADD_CATEGORY, UPDATE_CATEGORY, DISABLE_CATEGORY. מצבים: pending, sending, uncertain, synced, conflict, retry_wait, blocked, failed, cancelled. לאחר קריסה sending הופך uncertain; אין לשלוח שוב בעיוורון. פעולות קשורות מסודרות לפי sequence ותלויות. איחוד רק לפעולות שטרם נשלחו; בסיס ראשון, שינוי אחרון. לא לאחד פעולות בלתי ודאיות. שמירת פעולות שנכשלו עד פתרון מפורש.

### מיזוג
השוואה משולשת B=מקור, L=מקומי, R=ענן. L=R: אין כתיבה; L=B: קבלת R; R=B: שליחת L; אחרת התנגשות. כמות ויחידה הן קבוצה לוגית אחת. שדות בלתי תלויים ניתנים למיזוג. מחיקה גוברת בתצוגה עם חיווי לעריכה שלא נשמרה. פתרון מתמשך עם בדיקה מחדש. חסימת תלויות בלבד. שינויים מקבילים באותו שדה עלולים לדרוס זה את זה בין הקריאה לכתיבה; אין CAS מובנה במודל שנבחר. Batch אטומי אינו עסקה מותנית. אימות לאחר כתיבה אינו מבטל מרוץ זה. אם POC אינו מתקבל, בחינת OperationsLog באותו קובץ לפני שינוי ארכיטקטורה.

### יצירה והתאוששות
יצירת רשימה מקומית עם UUID; הקמת קובץ Drive עם appProperties בבקשת היצירה; אתחול Items/Categories/Metadata; כתיבת תמונת מצב מוגדרת; אימות ורק אז ready; שינויים מאוחרים נשארים בתור. במקרה של תשובה חסרה חיפוש לפי list_id ובדיקות חוזרות לפני יצירה; Google Workspace אינו תומך במזהה מראש לקובץ Sheets. אם נותר ספק, לעצור ולבקש טיפול במקום להסתכן ביצירה נוספת. אין הבטחת exactly-once. הוספת פריט באמצעות append עם UUID קבוע; חיפוש UUID לפני retry; כפילות טכנית מסומנת לבדיקה. הוספות עצמאיות עם מזהים שונים נשמרות ומוצע איחוד.

### פעולות מורכבות
Undo 5 שניות: ביטול פעולה שלא נשלחה או פעולת שחזור לאחר אימות; לא להחיות מחיקה אחרת באופן עיוור. איפוס סימונים חל על מזהי פריטים שסומנו בעת הפעולה, לא על כל הענן; שינוי Boolean הלוך ושוב עלול לחמוק מזיהוי. שכפול מקומי: מזהה רשימה ופריטים חדשים, מחלקות והערות נשמרות, פריטים מחוקים אינם מועתקים, סימונים מאופסים, אין העתקת הרשאות. שכפול Offline מותר רק לרשימה שבבעלות החשבון הנוכחי. לרשימה משותפת נדרש חיבור ובדיקה עדכנית של הרשאות Google החלות, לרבות canCopy לפי העניין.

### תזמון ושגיאות
Polling 10 שניות לרשימה פעילה; Push יזום; debounce מוצע 500ms; רענון אחרות בפתיחה וכל 5 דקות מוצעות; ברקע ללא Polling; חזרה לפוקוס/רשת/הרשאה מפעילה סנכרון. מוסתרות אינן מאבדות תור. 401 חידוש הרשאה; 403 הבחנה מכסה/גישה; 404 לא הוכחה למחיקה; 429/5xx backoff עם jitter ו-Retry-After אם קיים; כתיבה לא ודאית דורשת אימות. 400 בדיקת בקשה. navigator.onLine אינדיקציה בלבד. מכסות Sheets נפרדות לקריאה ולכתיבה: לבדוק בפועל במסוף; תיעוד ברירת מחדל 300 לפרויקט ו-60 למשתמש לפרויקט לדקה לכל סוג. לצמצם בקשות באמצעות batchGet ו-batchUpdate. אין התחייבות לסנכרון ברקע.

## 9. OAuth, Drive ו-Sheets
GIS Token Model, scopes: drive.file, openid, email; לא drive/spreadsheets רחבים. Token בזיכרון בלבד, אין refresh token או client secret בדפדפן. UserInfo לבדיקת sub של האסימון בפועל לפני כל החלפת חשבון/חידוש. אסימון שפג אינו מבטל עבודה מקומית. חידוש באמצעות פעולה יזומה של המשתמש. התנתקות, החלפת חשבון וביטול OAuth הן פעולות שונות. אין לשלוח תור של חשבון אחד באסימון אחר.
Drive v3: files.create/list/get/update, permissions.list/create/update/delete. files.list לפי MIME, trashed=false ו-appProperties, pagination; סיווג ownedByMe. capabilities.canEdit/canShare/canRename/canTrash/canCopy/canDownload לפי צורך. אין files.delete. שיתוף פרטי לפי מייל; writersCanShare=false ככל שנתמך. Picker עם token, project number, API key מוגבל, origin, מסנן Sheets. בעל הרשימה משתף; משתתף בוחר ב-Picker ומאשר גישה; אימות schema ומאפיינים. לא להניח שהשיתוף ב-Drive נותן אוטומטית הרשאת אפליקציה.
Sheets v4: spreadsheets.get, spreadsheets.batchUpdate לאתחול/מבנה, values.batchGet לטעינה, values.append להוספה, values.batchUpdate לעדכון נקודתי. טווחי Items A:J, Categories A:D, Metadata A:B; לבדוק כותרות לפני כתיבות. REST באמצעות fetch ומודול API אחיד. אין API ישיר מתוך UI.

## 10. אבטחה ופרטיות
מפתחות ציבוריים: Client ID, project number, API key מוגבל ל-Picker ולמקורות הנדרשים (כולל docs.google.com לפי תיעוד Google). אין סיסמאות או tokens במאגר/מטמון/לוגים. קלט מהגיליון לא מהימן; textContent, ללא innerHTML דינמי או eval. CSP באמצעות meta בכפוף לתמיכת GIS/Picker; הגבלות מטא אינן שקולות לכותרות HTTP. חשבון GitHub ייעודי כדי לבודד Origin; נתיבים אינם גבול אבטחה. 2FA והגנת הרשאות כתיבה. ללא analytics או דיווח חיצוני. מדיניות פרטיות ציבורית לפני כניסה: מטרות, נתונים מקומיים/ענן, הרשאות, מחיקה, ביטול גישה, מגבלות Offline. Google/GitHub עשויים לעבד מידע טכני. אין לטעון שהמפתח אינו יכול תאורטית לשנות את הקוד; התחייבות לא לאסוף תוכן.
בעת התנתקות ברירת המחדל מחיקה מקומית אחרי סנכרון או אישור אובדן מפורש; הצעת שמירה נעולה בממשק אינה הצפנה. חשבון אחר אינו רואה נתוני הקודם בממשק. ביטול הרשאת שיתוף אינו מוחק עותק ממכשיר מנותק. יש להבחין בין תקלה זמנית לביטול. בירידה לצפייה שומרים פעולות חסומות ומציעים עותק רק בחיבור ובכפוף להרשאות. אחרי אימות ביטול גישה מלא מסתירים את הרשימה מגישה רגילה, לרבות מסך הרשימות שהמשתמש הסתיר בעצמו, עוצרים סנכרון ושומרים פעולות ממתינות כ-blocked עד לפתרון מפורש. אין לאפשר שכפול מלא של הרשימה.

## 11. PWA ופרסום
Manifest: lang=he, dir=rtl, display=standalone, id יציב, start_url/scope יחסיים, אייקונים 192/512 ומסכה. Service Worker מטמון גרסאות עקבי של כל מעטפת האפליקציה וקטלוגים, ללא תשובות API פרטיות. לא להגיש HTML מגרסה אחת עם מודולים מגרסה אחרת. עדכון בהסכמת משתמש; שימור תור ומעבר schema/DB בדוק; אין skipWaiting כפוי במהלך שימוש. בדיקות POC ב-macOS וב-iPhone אמיתי. בדיקת Android במכשיר אמיתי תתבצע לפני שחרור רשמי של תמיכה ב-Android. פתיחה ראשונה חייבת להיות מקוונת והכנת Offline צריכה להסתיים. התקנה אופציונלית.
GitHub Free ציבורי ו-HTTPS. כתובת ה-POC המיועדת מופיעה בהחלטה 41. פיתוח ב-Codex Web ובסביבת הענן במאגר הקיים, בענף משימה ועם PR לסקירה. main משמש לגרסה יציבה. פרסום דורש אישור מפורש. הייצור ישתמש ב-Origin ייעודי, ללא רכישת דומיין לפי התכנון הנוכחי. Cloud POC נפרד מייצור; קובצי ניסוי בלבד. Production ייצור קבצים חדשים; אם נדרש מעבר, Picker ואימות Metadata במקום הסתמכות על appProperties של פרויקט אחר. בדיקת דרישות OAuth audience, testing, domain/branding, privacy לפני ייצור; אין להבטיח אישור או אפס עלויות ללא אימות מסלול.

## 14. נושאים פתוחים / סיכוני שחרור
- אימות drive.file ו-Picker עם שני חשבונות, גילוי חוזר, UserInfo, מגבלות OAuth ודומיין.
- race בין קריאה לכתיבה, שורה שזזה, כפילות לאחר timeout, איפוס ABA, העברת מחלקה מקבילה.
- שמירה מקומית על macOS וב-iPhone, עדכון PWA תוך שמירת תור וחלונות מרובים. Android ייבדק לפני שחרור תמיכה.
- אימות הטיפול בהרשאות שכפול, בביטול גישה מלא ובהתנגשות בין list_id ל-spreadsheet_id לפי החלטות 42–44.
- פרמטרי debounce, backoff ורענון רשימות אחרות הם מוצעים; גודל קטלוג ועיצוב סופי טרם הוכרעו.
- טרם בוצע ניסוי אמיתי; אין לטעון שהמערכת בנויה או שכל הסיכונים נפתרו. המסמך מאחד את ההחלטות בשיחה ולא מהווה אישור לתוספות שטרם נדונו.
