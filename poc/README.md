# בדיקת חיבור ורשימת קניות ב־Google

המסך בודק חיבור דרך Google Identity Services, מאמת את שלוש ההרשאות הדרושות ומזהה את החשבון באמצעות `sub` מ־UserInfo. בדיקת Drive מבצעת `GET files.list` ומבקשת דף בגודל פריט אחד. גם דף ריק הוא תוצאה תקינה במסגרת `drive.file`.

## הגדרה

לאחר פרסום מאושר, פתחו את כתובת ה־[POC ב־GitHub Pages](https://zoharkolberg.github.io/shoping_list/poc/). העתיקו את מזהה הלקוח מסוג Web application מפרויקט Shopping List POC לשדה **OAuth Client ID** ולחצו על **שמירת הגדרה**. ה־Authorized JavaScript origin הוא `https://zoharkolberg.github.io`. מזינים את ה־Client ID בכל פרופיל דפדפן ובכל מכשיר בנפרד. לניקוי ההגדרה רוקנו את השדה ושמרו.

ה־Client ID הציבורי נשמר ב־`localStorage`. האסימון, האימייל, `sub` ויומן האבחון חיים בזיכרון הדף. התנתקות מקומית מוחקת את פרטי החיבור מהדף. את ההסכמה אפשר לבטל בהגדרות חשבון Google.

### שחזור בדיקת כתיבה חיה של טקסט דמוי נוסחה (S01)

1. בקובץ דמה במצב `ready`, לחצו על **הוספת פריט דמה**. לחצו על **טעינה או קריאה חוזרת**, ואתרו את הפריט לפי `item_id`. בשדה ההערה במסך אמור להופיע הטקסט המדויק `=1+1`.
2. לחצו על **פתיחה ב־Google Sheets**. בלשונית `Items`, מצאו את אותו `item_id` בעמודה A ובדקו שבעמודה G מוצג הטקסט `=1+1` בתא עצמו. תוצאה מחושבת `2` היא כשל. הזנת הטקסט ידנית בגיליון עוקפת את מסלול הכתיבה הנבדק.
3. אם כלי הרשת פתוח, בדקו רק ש־append משתמש ב־`valueInputOption=RAW` ושקריאת `batchGet` משתמשת ב־`valueRenderOption=UNFORMATTED_VALUE`. בתיעוד התוצאה השמיטו כותרות HTTP, אסימונים ונתוני חשבון.

### עצירה ובדיקה חוזרת של כתיבה

1. אם כתיבה לא אומתה, השאירו את הדף פתוח. אם החיבור פג, התחברו מחדש באותו דף עם אותו חשבון ואותו OAuth Client ID. לחצו על **בדיקת כתיבה שטרם אומתה**. לאחר `429` או תקלה זמנית, המתינו שהשירות יחזור לפני הבדיקה הידנית.
2. בהתאוששות מיצירה המסך מאתר את הקובץ לפי `list_id` ומאמת את הבעלות, מזהה הקובץ ומבנה האתחול. רק תמונת אתחול מלאה ותקינה מאפשרת מעבר מ־`initializing` ל־`ready`. בהתאוששות מכתיבת פריט המסך משווה את הערכים שנקראו לפי `item_id` לערכים שנשלחו.
3. אם הקובץ לא נמצא, זוהתה כפילות, או שהקובץ נשאר `initializing` בגלל אתחול חלקי, עצרו את תרחיש הכתיבה. השתמשו ב־**גילוי גיליונות דמה** כדי לראות את המצב ולתעד את `list_id` או `item_id` ואת מזהה הגיליון, ככל שהם זמינים. השאירו את הקובץ לבדיקה. אין לאתחל ידנית את הקובץ, לשנות את הסימון ל־`ready` או ליצור קובץ חלופי במסגרת אותה בדיקה. פעולות הכתיבה באותו חשבון ו־Client ID נשארות מושהות בדף כל עוד התוצאה לא אומתה.
4. אם חייבים לסגור את הדף, תעדו תחילה את המזהים ואת סטטוס **תוצאה לא ידועה**. אחרי פתיחה מחדש, השתמשו בגילוי ובקריאה לאבחון לפי המזהים שתועדו. סגירת דף או רענון מסירים את מצב ההמתנה שבזיכרון ואינם מאשרים שהכתיבה נכשלה או הצליחה. לתרחיש מבוקר של אובדן תשובה, השתמשו בבדיקות המדומות.

### שחזור בדיקת מחלקות

בקובץ דמה נפרד, הוסיפו ל־`Categories` מחלקה עם UUID תקין, שם דמה, `is_builtin=FALSE` ו־`active=FALSE`. שייכו אליה פריט דמה דרך עמודה E וקראו מחדש. הפריט אמור להופיע תחת ״אחר״ עם חיווי תיקון, תוך שמירת ה־UUID בשורה. החליפו את השיוך ב־UUID שאינו קיים או את `unit_id` במזהה שאינו `piece`, ובדקו שהקובץ נדחה. ה־POC משתמש ב־`piece` כיחידה היחידה, ב־`other` כמחלקה המובנית הפעילה וב־UUID למחלקות מותאמות.

עדכונים משתמשים בכתובות A1 לאחר קריאה ואימות UUID. עדיין יש חלון מרוץ בין הקריאה לכתיבה. Developer Metadata וניסוי כתיבה לשורה שזזה נותרו לשלב עתידי. שער 1 עדיין פתוח.

## בדיקות Task 005 לשער 1

בדיקות השיתוף ו־Picker מול Google עדיין **NOT RUN**. הריצו אותן עם שני חשבונות הבדיקה וקובצי דמה חדשים לאחר אישור הגשת גרסת הבדיקה. תעדו commit, גרסאות מערכת ודפדפן, קוד HTTP או סטטוס מסונן לכל פעולה ותוצאת PASS, FAIL או BLOCKED. השמיטו אסימונים, כותרות Authorization, אימיילים, מזהי קבצים ומפתחות מתיעוד ציבורי.

### הגדרת Picker בידי הבעלים

- בגרסה מאושרת המוגשת מה־Origin של לקוח ה־OAuth, הזינו ב־**Google Picker ואבחון גישה** את **מספר הפרויקט** של Shopping List POC ואת מפתח ה־API הציבורי. הלקוח, המספר והמפתח צריכים להשתייך לאותו פרויקט Google Cloud. מספר הפרויקט שונה ממזהה הלקוח.
- בדקו ש־Drive API, Sheets API ו־Google Picker API זמינים בפרויקט. הגבלות המפתח צריכות להתיר רק את Picker API ואת ה־HTTP referrer של אתר ה־POC. עבור Pages, ה־Origin הוא `https://zoharkolberg.github.io`. הגדירו שינויי Cloud רק לאחר אישור הבעלים.
- השדות הציבוריים של Picker נשארים בדף עד לרענון. הזינו אותם מחדש בכל מכשיר. השיתוף שולח את האימייל שהוזן ל־Drive והטופס מנקה אותו לאחר השליחה. כתובות בהרשאות קיימות מוצגות לבעלים בזיכרון הדף בלבד. תוצאות האבחון אינן מציגות אותן. האפשרות לשליחת הודעת הזמנה של Drive כבויה.

### יתר בדיקות שער 1

- **A01/A02.** שחזרו כניסה, אימות שלוש ההרשאות וקריאת Drive בשני החשבונות. ב־macOS השהו תגובת קריאה במהלך בדיקה מקדימה לכתיבת פריט דמה עם A באמצעות כלי הרשת של הדפדפן או תרחיש מדומה מבוקר. החליפו ל־B לפני החזרת התגובה. אפסו את ההשהיה ובדקו שאף כתיבה לא נשלחה עם B ושבחירת הגיליון, הפריטים, ההרשאות ותוצאות Picker נוקו. אם כתיבת A כבר נשלחה, היא עשויה להגיע ל־Google עם אסימון A. בדקו גם החלפה בזמן ש־Picker פתוח. תעדו כיסוי מדומה וביצוע חי בנפרד.
- **A03/A04.** בדקו תפוגה וביטול הסכמה בחשבון הבדיקה, עצירת כתיבות וחיבור מחדש בעקבות לחיצה. עם B בדקו `files.get` ו־`files.list` מול גיליון דמה אחר שהאפליקציה טרם הורשתה לפתוח. בטלו את הבדיקה לפני Picker ותעדו את תוצאת הגישה.
- **D01–D03/S01.** השתמשו בהוראות Task 004 לעיל. השלימו את אימות ערכי `appProperties` ומעבר האתחול, וכן שינוי שם תוך שמירת תחילית הדמה והעברה לתיקייה אחרת, עם גילוי חוזר והשוואת שני המזהים. שחזרו את בדיקת RAW אם גרסת הבדיקה מחייבת זאת.
- **H01 ב־Safari באייפון אמיתי.** פתחו את כתובת Pages שאושרה לגרסת הבדיקה. הזינו את הגדרות OAuth ו־Picker, התחברו כ־B, אשרו את שלוש ההרשאות ובחרו גיליון דמה משותף. בדקו ביטול, בחירה חוזרת, קריאה בפועל של אותו גיליון וחיבור מחדש וגילוי ללא Picker. תעדו דגם וגרסת iOS, תוצאות וסביבת הבדיקה. התקנת PWA ובדיקת מצב טיסה מתועדות ב־O06.

שער 1 פתוח עד לקבלת תוצאות הבדיקות החיות המלאות. כאשר `appProperties` חסרים בקובץ משותף, תחילית הדמה, ה־Metadata וסכמת הגיליון משמשים לאימות. בדיקת כפילות חלה על קבצים שהאפליקציה מורשית לגלות או לקרוא. בדיקת הרשאות סמוכה לכתיבה מצמצמת את חלון הזמן לשינוי הרשאות. Google מכריעה בזמן קבלת הבקשה.
