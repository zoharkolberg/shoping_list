# בדיקת חיבור ורשימת קניות ב־Google

המסך בודק חיבור דרך Google Identity Services, מאמת את שלוש ההרשאות הדרושות ומזהה את החשבון באמצעות `sub` מ־UserInfo. בדיקת Drive מבצעת `GET files.list` ומבקשת דף בגודל פריט אחד. גם דף ריק הוא תוצאה תקינה במסגרת `drive.file`.

## הגדרה

לאחר פרסום מאושר, פתחו את כתובת ה־[POC ב־GitHub Pages](https://zoharkolberg.github.io/shoping_list/poc/). העתיקו את מזהה הלקוח מסוג Web application מפרויקט Shopping List POC לשדה **OAuth Client ID** ולחצו על **שמירת הגדרה**. ה־Authorized JavaScript origin הוא `https://zoharkolberg.github.io`. מזינים את ה־Client ID בכל פרופיל דפדפן ובכל מכשיר בנפרד. לניקוי ההגדרה רוקנו את השדה ושמרו.

ה־Client ID הציבורי נשמר ב־`localStorage`. האסימון, האימייל, `sub` ויומן האבחון חיים בזיכרון הדף. התנתקות מקומית מוחקת את פרטי החיבור מהדף. את ההסכמה אפשר לבטל בהגדרות חשבון Google.

## בדיקות ידניות לאחר פרסום מאושר

1. ב־macOS פתחו את כתובת ה־POC בשני פרופילי דפדפן עם חשבונות הבדיקה A ו־B. הגדירו את הלקוח בכל פרופיל. התחברו, בדקו שהאימייל נכון, שכל שלוש ההרשאות אומתו ושמוצג מועד תפוגה. הפעילו את בדיקת הקריאה.
2. באחד הפרופילים התחילו בדיקת קריאה ולחצו על **חיבור מחדש או החלפת חשבון**. בחרו בחשבון השני ובדקו שרק האימייל החדש מוצג ושתוצאת Drive מתאפסת. הפעילו בדיקת קריאה שוב.
3. סגרו את חלון ההרשאה במהלך ניסיון חיבור ובדקו שמוצג חיווי מתאים. כדי לבדוק סירוב או הסכמה חלקית, השתמשו בחשבון בדיקה ללא הסכמה קודמת או בטלו קודם את ההסכמה לחשבון הבדיקה בהגדרות Google. בדקו שכפתור Drive מושבת כשההרשאות חסרות.
4. המתינו לתפוגת האסימון ובדקו שקריאת Drive מושבתת ושחיבור מחדש דורש לחיצה. בדקו גם שהתנתקות מקומית מסירה את האימייל ותוצאת Drive, ושרענון הדף דורש חיבור מחדש.
5. ב־Safari ב־iPhone אמיתי פתחו את אותה כתובת, הזינו את ה־Client ID ובדקו התחברות, הרשאות, קריאה, ביטול החלון וחיבור מחדש. בדקו את התצוגה לאורך ולרוחב. תעדו גרסת דפדפן ומערכת, סטטוס ותוצאה מסוננת.

## תוצאות Task 003 ו־003.1

בעל הפרויקט דיווח **PASS** על פתיחת דף ה־POC ב־GitHub Pages, שמירת ה־Client ID, פתיחת חלון ההרשאה, חיבור חשבון A, אימות שלוש ההרשאות, הצגת האימייל הנכון ומועד תפוגת האסימון, וקריאת Drive לקריאה בלבד. חשבון B והחלפת חשבונות נדחו. פקיעת אסימון וביטול הרשאה בפועל, סגירת החלון, סירוב והסכמה חלקית, בדיקת קובץ ללא הרשאה ובדיקות iPhone נשארו **NOT RUN**.

## בדיקת Task 004 עם חשבון A

השתמשו בחשבון הבדיקה ובנתוני דמה בלבד. דרושים Drive API ו־Sheets API פעילים בפרויקט הבדיקה, וגרסת הענף מוגשת ב־Origin שכבר אושר ללקוח OAuth. גרסת Pages החיה משמשת כבסיס ל־Task 003. בדיקות Task 004 החיות מסומנות **NOT RUN**.

1. פתחו ב־macOS את גרסת הבדיקה של הענף. הזינו את ה־Client ID, התחברו עם חשבון A וודאו שמוצגות שלוש ההרשאות. הפעילו שוב את בדיקת הקריאה מ־Drive.
2. לחצו על **יצירת גיליון דמה**. ודאו שמוצגים מזהה גיליון ו־`list_id` ושמצב האתחול הוא `ready`. לחצו על **פתיחה ב־Google Sheets**. ודאו שנפתח קובץ הדמה החדש בבעלות A ושיש בו `Items`, `Categories` ו־`Metadata`. השוו את הכותרות לסעיף 5 באפיון, את `list_id` לערך במסך ואת מחלקת `other` הפעילה.
3. לחצו על **גילוי גיליונות דמה**, בחרו את הקובץ ולחצו על **טעינה או קריאה חוזרת**. לחצו על **הוספת פריט דמה** ובדקו שנוספה שורה אחת עם מזהה חדש.
4. בחרו בפריט החדש, הזינו 2.5 ולחצו על **שמירת כמות**. בחרו שוב באותו פריט ולחצו על **סימון כנרכש**. קראו שוב ובדקו שכמות 2.5 והסימון נשמרו באותה שורה. בגיליון, הכמות צריכה להיות מספר והסימון `TRUE`.
5. בחרו שוב באותו פריט ולחצו על **מחיקה לוגית**. קראו שוב ובדקו שבגיליון השורה והמזהה נשארו באותו מקום, עם `deleted=TRUE`, ושהפריט אינו מוצע עוד לבחירה לעריכה.
6. רעננו את הדף והתחברו שוב עם A. גלו וטענו את הקובץ ובדקו שהמזהים והערכים נשמרו. אפשר גם להעביר את קובץ הדמה לתיקייה אחרת ולשנות את הסיומת של שמו תוך שמירה על התחילית `[Shopping List POC] `, ואז לבדוק גילוי חוזר.
7. לבדיקת סכמה, השתמשו בקובץ דמה נפרד שיצרתם דרך ה־POC. שנו את אחת הכותרות ב־`Items` ובדקו שהגילוי מזהה את הבעיה ושהכתיבה חסומה. שחזרו את הכותרת. הוסיפו פריט דמה, שכפלו את שורתו עם אותו `item_id` ובדקו שהכתיבה חסומה. תרחיש שני קבצים עם אותו `list_id` כלול בבדיקות המדומות.
8. אם חיבור נקטע בזמן כתיבה ומופיע מזהה לבדיקה, חברו מחדש את אותו חשבון באותו דף ולחצו על **בדיקת כתיבה שטרם אומתה**. תוצאה שלא אותרה נשארת ממתינה. אם נמצא קובץ `initializing` שתכולתו אינה שלמה, תעדו את מצבו לפני יצירת קובץ נוסף. לתרחיש שחזור מבוקר עם אובדן תשובת Google, השתמשו בבדיקות המדומות.
9. תעדו לכל בדיקה את גרסת הדפדפן, ה־commit, התוצאה וראיה מסוננת. השאירו את חשבון B, החלפת חשבונות, יתר מקרי הקצה של OAuth וניסויי iPhone במצב **NOT RUN** או **DEFERRED** עד לביצוע בפועל.

עדכונים משתמשים בכתובות A1 לאחר קריאה ואימות UUID. עדיין יש חלון מרוץ בין הקריאה לכתיבה. Developer Metadata וניסוי כתיבה לשורה שזזה נותרו לשלב עתידי. מצב ההמתנה של כתיבה קיים בזיכרון הדף לפי חשבון ו־Client ID ואובד בטעינה מחדש. הגילוי המחודש מוצא קבצים שהופיעו ב־Drive, כולל קובצי דמה באתחול חלקי. תיתכן השהיה עד שהקובץ יופיע ב־Drive. שער 1 עדיין פתוח.

## בדיקות אוטומטיות

פקודות הרצה ודרישות הפיתוח נמצאות ב[מדריך הבדיקות](../tests/README.md). אם טעינת GIS נכשלת או נמשכת מעל 15 שניות, אפשר לטעון את הדף מחדש. לניסיון הרשאה יש חלון של שתי דקות לקבלת תשובת Google. אפשר לבטל אותו בכל עת ולהתחיל מחדש.
