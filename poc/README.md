# בדיקת חיבור ל־Google

המסך בודק חיבור דרך Google Identity Services, מאמת את שלוש ההרשאות הדרושות ומזהה את החשבון באמצעות `sub` מ־UserInfo. בדיקת Drive מבצעת `GET files.list` ומבקשת דף בגודל פריט אחד. גם דף ריק הוא תוצאה תקינה במסגרת `drive.file`.

## הגדרה

לאחר פרסום מאושר, פתחו את כתובת ה־[POC ב־GitHub Pages](https://zoharkolberg.github.io/shoping_list/poc/). העתיקו את מזהה הלקוח מסוג Web application מפרויקט Shopping List POC לשדה **OAuth Client ID** ולחצו על **שמירת הגדרה**. ה־Authorized JavaScript origin הוא `https://zoharkolberg.github.io`. מזינים את ה־Client ID בכל פרופיל דפדפן ובכל מכשיר בנפרד. לניקוי ההגדרה רוקנו את השדה ושמרו.

ה־Client ID הציבורי נשמר ב־`localStorage`. האסימון, האימייל, `sub` ויומן האבחון חיים בזיכרון הדף. התנתקות מקומית מוחקת את פרטי החיבור מהדף. את ההסכמה אפשר לבטל בהגדרות חשבון Google.

## בדיקות ידניות לאחר פרסום מאושר

1. ב־macOS פתחו את כתובת ה־POC בשני פרופילי דפדפן עם חשבונות הבדיקה A ו־B. הגדירו את הלקוח בכל פרופיל. התחברו, בדקו שהאימייל נכון, שכל שלוש ההרשאות אומתו ושמוצג מועד תפוגה. הפעילו את בדיקת הקריאה.
2. באחד הפרופילים התחילו בדיקת קריאה ולחצו על **חיבור מחדש או החלפת חשבון**. בחרו בחשבון השני ובדקו שרק האימייל החדש מוצג ושתוצאת Drive מתאפסת. הפעילו בדיקת קריאה שוב.
3. סגרו את חלון ההרשאה במהלך ניסיון חיבור ובדקו שמוצג חיווי מתאים. כדי לבדוק סירוב או הסכמה חלקית, השתמשו בחשבון בדיקה ללא הסכמה קודמת או בטלו קודם את ההסכמה לחשבון הבדיקה בהגדרות Google. בדקו שכפתור Drive מושבת כשההרשאות חסרות.
4. המתינו לתפוגת האסימון ובדקו שקריאת Drive מושבתת ושחיבור מחדש דורש לחיצה. בדקו גם שהתנתקות מקומית מסירה את האימייל ותוצאת Drive, ושרענון הדף דורש חיבור מחדש.
5. ב־Safari ב־iPhone אמיתי פתחו את אותה כתובת, הזינו את ה־Client ID ובדקו התחברות, הרשאות, קריאה, ביטול החלון וחיבור מחדש. בדקו את התצוגה לאורך ולרוחב. תעדו גרסת דפדפן ומערכת, סטטוס ותוצאה מסוננת.

כל בדיקות Google ו־GitHub Pages החיות במצב **NOT RUN**. בדיקות Picker, כתיבה, שיתוף וסנכרון שייכות לשלבים הבאים. בדיקת קריאה מוצלחת אינה משלימה את שער 1 של תוכנית ה־POC.
